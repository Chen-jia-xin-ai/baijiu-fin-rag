# 白酒财报问答知识库

> 作业 3 · 方向 A：下载财报，做一个问答知识库
>
> 白酒 12 家上市公司 × 4 期财报（2023/2024/2025 年报 + 2026 半年报）= 48 份 PDF 全文。
> 表格按行列还原、每个块自带公司/报告期/章节/页码、向量 + BM25 混合检索、
> 答案带出处，并用 10 道题（含 2 道跨公司）逐题记录「召回了什么、答对没有、错在哪」。

| 步骤 | 文件 | 动作 |
|---|---|---|
| 1/6 取数 | `scripts/01_download.py` | 从巨潮资讯网反查 orgId、检索公告、下载 48 份 PDF，落 `data/manifest.jsonl` |

## 二、这套设计要回答的问题

作业最后一问是：**同一批财报，什么问题该建库、什么问题该微调？**

做完之后的判断是 **三桶，不是两桶**：

| 桶 | 装什么 | 为什么不是另一个 |
|---|---|---|
| **可检索的库** | 带日期、带版本的事实（某年某公司的某科目余额、某次分红方案） | 微调会把 FY2023 的数字张口就用到 FY2026 的问题上；而且微调**给不出出处**，而「答案带出处」正是本题的硬要求 |
| **表格工具**（pandas over `data/tables/*.jsonl`） | 算术、排名、全库聚合（「12 家里销售费用率最低的是谁」） | 朴素 RAG 的**结构性盲区**：top-k 只给你几页，给不了全量；微调同样不行，它没有可枚举的输入 |
| **权重** | 口径、文风、输出格式（稳定的带引用对比表） | 12 家公司、约 16MB 文本远不足以把事实装进参数；但对学**格式**刚好合适 |

第 7、8 题是**故意设计的翻车题**——它们翻车不是缺陷，是上面这张表的证据。
`scripts/05_eval.py` 里有一段 pandas 兜底，把同样的问题算得又对又精确，
并排放在结果里对照。

## 三、四个决定成败的实现细节

### 1. 每个块的嵌入文本自描述

索引的不是 `text`，而是**前面拼了一行上下文头的 `embed_text`**：

```
【贵州茅台 600519 | 2025年年度报告 | 第九节财务报告 / 七、合并财务报表项目注释 | 合并 | 表格(单位:元) | 第58页】
单位:元 | 项目=合同负债 | 附注=29 | 2025 年12 月31 日=8,006,739,780.94 | 2024 年12 月31 日=9,592,453,014.66
```

这一行同时解决四件事，缺了它后面怎么调都补不回来：

1. **跨公司对比不串味**——公司名进了向量和 BM25 的词表；
2. **章节 / 页码变成可检索字段**；
3. **出处不用猜**（模型只准引用服务端给的编号）；
4. **合并 / 母公司两套口径可区分**——同一个科目两张表，数字不同。

没有它，一个写着「期末余额 1,234」的块在 12 家公司里向量上无法区分，
所有全景题都会塌向语料占比最大的那家。

### 2. 表格行线性化，不用管道表

管道表格会把「合同负债」和「8,006,739,780.94」隔开几百个 token，
分块之后行标签和数值大概率落进不同的块——「合同负债是多少」这种问题就永远捞不回来。

所以索引用的是**行线性化**：`项目=合同负债 | 2025 年12 月31 日=8,006,739,780.94`，
行标签紧挨它自己的数值。markdown 管道表另存一份，只给前端渲染用。

### 3. 跨公司问题必须分路检索——但「分路」不等于「各取 15 条再按分排」

融合出来的单一 top-5 会被其中一家霸榜——
「汾酒和泸州老窖谁的营业收入高」的全局 top-5 很可能全是汾酒，因为两家的措辞高度相似。

第一轮的做法是检查询里点到的公司（12 家别名表），命中 2 家以上就**逐家各检索一次、
各取 15 条、再按融合分合并**。**测下来这个改动没有用**：`hybrid` 与 `hybrid-noroute`
并排跑，recall@5 是 5/15 对 5/15，MRR 0.398 对 0.401——关掉分路甚至略好。

原因在合并那一步：汾酒那一家的段落在融合分上**普遍**高于泸州老窖，
所以「各取 15 条再排序」等于没分路，前 5 名照样被一家占满。
Q5 实测 top-5 里 4 条是山西汾酒（还全是 FY2023 和 H1-2026 的），泸州老窖**一条都没有**——
题目直接答不成立。

第二轮改成**配额占位**：每家公司先拿走 `ceil(top_k / 家数)` 个名额，
谁分高谁先填，但没有任何一家能把别人挤光；剩余名额再按名次轮流补。
排名顺序保留轮流占位的顺序，不按分重排——**存在性比分数重要**。

### 4. 行级索引：把粒度从「页」降到「行」（第二轮加的最重要一处）

第一轮评测最刺眼的失效模式，**不是**跨公司塌陷，是
**「答案就在那张表里，可表被切成了五块，行标签和它的数字落在了不同块」**。

一张合并资产负债表的线性化文本有两三千字，按 900 字切就是三到四块
（茅台 2025 年末那张表被切成 p56 / p57 / p57续 / p58 / p59 五块），
「合同负债」那一行具体掉进哪一块**纯属运气**。于是：
Q3 答对了（top-5 里恰好有装着那一行的块），Q8 问的是同一张表里的同一个数，却答不出来
（top-5 里的块都对，只是没有一个装着那一行）。

修法不是加重排器，是把粒度降下来：`scripts/08_rows.py` 把 `tables.jsonl` 里
**6.7 万条结构化行**每条单独做成一个「只装一行」的检索单元，自描述前缀照旧，
同时建 BM25 和向量。词法路径靠行标签精确命中，向量路径靠语义兜底。

顺带一个更要紧的好处：行级单元天然带 `scope`（合并 / 母公司）和 `period` 两个字段。
第一轮里 Q4（母公司应付账款）只排到第 6 名，根因就是**口径在向量空间里几乎不可分**——
`合并资产负债表` 和 `母公司资产负债表` 的两行字，bge-small 分不出高下。
把口径变成**一个布尔过滤条件**之后，这个区分就不再依赖模型的分辨率。

## 四、踩坑实录

**`doc.get_toc()` 在这个语料里是垃圾。** 茅台返回 617 条书签，内容是 `OLE_LINK18`、
`一、本公司董事会……` 这种正文段落；五粮液返回 0 条。所以章节识别只能靠
**字号定候选 + 正则定层级**，而且层级必须在**当前节的作用域内**判——
`一、` 在每一级都复现，不给嵌套作用域根本没法消歧。

**合并表头的前向填充会吃掉真表头。** `衍生金融负债 / 应付票据` 之类的空行会被
当成跨列合并的表头，把 4 列全填成同一个词。第一次修得太狠（单单元格行直接
`return 0`），结果整张表的表头被丢掉；正确的修法是**`break`（停止扫描）而不是
`return 0`（否定整张表）**——因为 `流动资产：` 这种小节标签就长这样。

**续页没有表头。** 合并资产负债表跨页印刷，第 59 页上方什么都没有，表头在第 58 页。
加了跨页继承，但必须用「表 bbox 顶边 < 页高 15%」和「距上表 ≤ 2 页」两道闸门卡住，
否则一个标题会粘到几十页之后的表上。

**续页的物理列数对不上首页的物理列数——所以「列数相等才继承」这条判据让 12 家全线失守。**
报表首页被 PyMuPDF 判成 3 列（项目 / 期末余额 / 期初余额），续页却是 4 列、9 列：
多出来的是**「附注」那一列**，首页填了附注号，续页整列空白。
一比 `ncols` 就不相等，于是每一页续表的列名都退化成 `列3 / 列4`——
行标签在、数字在，**列名没了**，「合同负债期末余额是多少」在续页上再也答不出来。
而资产负债表、利润表动辄跨 2-3 页，也就是最要紧的那几张表的**后半截全废**（实测 273 张）。
正确判据和 `_tidy_columns` 的收缩规则是同一套：先看**哪些列真的出现过值**，
再看这个数目对不对得上（今世缘 p56 四列里只有三列有值，继承成立）。
改完之后今世缘 `合同负债 → 1,708,006,613.73`、口子窖 `→ 334,464,339.40` 全部归位。

**财报标题会横着爬。** 口子窖 FY2025 的合并利润表在 p77-79，但它 p143 往后的四十来张
附注表 caption 全变成了「合并利润表。」——因为那些表也贴着页顶，
正好落进「紧贴页顶 + 有上一张财报标题」的继承分支。
后果不只是出处难看：`_scope_of()` 从 caption 里读口径，于是这些附注表**被判成「合并」**，
而它们本来什么口径都不是。修法是给 `state["statement"]` 配一个 `statement_page`，
继承只在 **3 页以内**生效。

**`str.splitlines()` 会吃掉 JSONL。** 财报正文里有 U+2028 / U+2029 行分隔符
（PDF 排版遗留）。它们在 JSON 里完全合法，`splitlines()` 却把它们当换行——
于是一条记录被切成两半，报 `Unterminated string`。山西汾酒 FY2023 和水井坊 FY2023 都中招。
读的时候只按 `\n` 切（`config.read_jsonl`），写的时候显式转义（`config.json_line`）。

**章节正则必须锚尾。** `STATEMENT_RE` 原来要求行首是「合并/母公司/资产负债表…」，
于是泸州老窖的 `3、合并利润表` 永远匹配不上——而它的标题还印在**上一页页脚**，
p79 那张表干脆拿不到 caption。加了可选编号前缀之后**必须同时补一个行尾锚点**，
否则 `1、利润表及现金流量表相关科目变动分析表` 变成假阳性，会粘到后面几十张表上。

**先对齐表头，再填充合并单元格——顺序反了就不可逆。**
`_tidy_columns` 要读**原始**表头位置来判断「哪个表头格离哪列数据最近」；
`_fill_spanning` 一跑，空表头格已被前向填满，原始位置就没了。
五粮液合并利润表就是这个顺序问题：表头非空在 1/4/7，数据在 1/3/6，
前向填充会把「2024 年度」填到第 3 列上，而第 3 列装的是 2024 年的数、顶着「项目」的名字——
**正文检索照样能跑，错得悄无声息。**

**单路模式的分数标签写反了。** `_fuse()` 里 `vector` 分支写成
`self._hit(i, 0.0, s, s, rank)`，参数顺序是 `(idx, 向量分, BM25 分, 融合分, 名次)`，
于是纯向量模式的所有命中都显示成「向量 0.0 / BM25 0.94」，纯 BM25 模式反过来。
消融表的每一格分数都是错的，而且错得很有说服力（数字看着都合理）。
**这种 bug 只能靠盯着一列数字问「这个 0 为什么正好在这里」发现。**

**`.gitignore` 里 `!例外` 救不回被排除目录里的文件。** 写了 `data/chunks/` 之后，
git 不再往这个目录里看，后面的 `!data/chunks/chunks.jsonl.gz` 永远不会生效。
得先排除目录**内容**（`data/chunks/*`）才能用 `!` 把单个文件捞回来。

**页眉页脚的两套过滤机制会互相打架。** 位置过滤先把 143 页里 133 页的页眉删掉，
剩下的 10 页低于重复率阈值，于是重复率过滤永远不触发。修法是把
`lines` 一律保留、把 `page_h` 存进记录，最后统一用「重复率 **且** 位置」判定。

**`单位` 在表外，而且各表不一。** 报表页是 `元`，管理层讨论常是 `万元`。
不处理会得到「数字对、量级错」，跨公司比较直接报废。

**「年度报告」是「半年度报告」的子串。** `kind = "annual" if "年度报告" in title else "semi"`
会把 12 家公司的半年报**静默**判成年报，然后用一个永远匹配不上的标题去搜。
先判 `半年度报告` 才对。

**金标写错，而且是「存在性校验」根本查不出来的那种。** Q2 问「2025 年度利润分配预案里每 10 股
派发现金红利多少元」，初版金标写 **239.57**，取自第 33 页正文。`verify_gold.py` 通过了——
239.57 确实在第 33 页。可是 239.57 是**中期**分红；真正回答「2025 年度合计」的 **279.93**
**只出现在一张表里**（同页「最近三个会计年度现金分红情况」的「每10股派息数」一栏），
正文全文没有这个数。更打脸的是第一次跑评测时**模型答对了这一点**——它明确说
「239.57 是中期方案，不是年度预案」，却被金标判成 CORRECT。回头看 PDF 才发现错的是金标。
校验规则只能验**存在性**，验不了**语义**：一个「在页面上存在、但答的不是这道题」的数字，
任何自动校验都拦不住。这一条只能靠人工回头看原始 PDF。

**二维码和目录点线会被当成正文抓下来，而且在向量上很「像」数据。**
今世缘 H1-2026 第 16 页整页是信息披露二维码，那两串验证码字符长、分布古怪，
向量上离「一张密密麻麻的数字表」并不远——第一轮里它们拿到 **BM25 220 分**、
冲进 Q4 的 top-5（第 2、4 名），而 Q4 要的是母公司资产负债表。
目录页（「第一节 重要提示、目录和释义 ………… 3」）同样会被 `find_tables` 当表格抓下来，
列名退化成 `列1 列2 列3`，内容全是点线。共 251 块，在检索层用
`retriever.is_junk_chunk()` 拦掉。**它们的问题不是「检索不到」，是「检索到了更糟」。**

**报告期写在文本里，和报告期是个字段，是两回事。** 自描述前缀里确实有「2025年年度报告」，
它也进了 BM25 词表。但 FY2023 年报里**逐字相同**的「可能面对的风险」段落，
在向量上同样像答案——Q1 的第 3、4 名就是茅台 FY2023 第 2 页和第 21 页，
第 5 名是 H1-2026 第 12 页，**全是正确的内容、错误的年份**。
BM25 更不帮忙：`2025` 和 `2023` 都是高 df 数字，在 BM25Plus 里几乎没有区分力。
这就是「该建库」的字面含义——**不是把事实埋进向量，是给事实结构化字段**，
让「2025 年度」从一段文风变成一个布尔条件。

**降到行粒度，会掉进「明细行压过合计行」的新坑。** 行级索引把「山西省内 / 山西省外 / 合计」
拆成三条**平级**的行，可营业收入分解表的**每一行**都复读了列名——`山西省内 | 合计 / 营业收入=13,390,549,706.80`。
于是问「山西汾酒的营业收入是多少」时，这一行在 row_vec 排第 1、row_bm25 排第 2，四路 RRF 的共识票把它顶上去；
而真正的合计行（第 5 页，`营业收入 | 2025年=38,718,257,657.74`）更长、只在单路径排第 5，被压掉。
Q5 因此从「部分对」退化到「错」。**修法不是加权重**——试过 row_vec ×2/×3 与砍掉 row_bm25，
recall@5 从 7/10 掉到 6/10——**是让行保留表的层级**：合计/小计是明细的父节点，扁平化时把这个结构丢了。
「按行列还原」的「按行」不止是拆行，还包括**行与行之间的关系**。

**水井坊 FY2023 的标题是「水井坊2023年度报告」**，年份和「年度报告」之间没有「年」字，
多数公司写「2025年年度报告」。正则得用 `年?` 容忍。

**orgId 不能猜。** 洋河 / 今世缘 / 迎驾贡 / 口子窖 是 `99000xxxxx` 形态；
手猜 `gssz0002304` 一类会稳定返回空列表，**而且不报错**。一律走 topSearch 反查。

**缺 UA / Referer 时巨潮返回 HTML 错误页，HTTP 状态码仍是 200。**
`.json()` 之前必须断言 Content-Type。

**git bash 里 `curl -d` 传中文会把 body 编码搞坏**（`invalid unicode code point`，HTTP 400）。
一律用 Python `requests` + `json=`。

**HuggingFace 直连不通（000）**，`hf-mirror.com` 通（200）。
`config.py` 里 `os.environ.setdefault("HF_ENDPOINT", "https://hf-mirror.com")`
**必须在 import fastembed 之前**执行。

**BM25 用 `BM25Plus`，不用 `BM25Okapi`。** Okapi 会给高 df 的词负 idf，
而「公司名」在这个语料里恰恰是高 df 词，负 idf 会让它起反作用。
